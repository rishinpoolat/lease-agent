# Codebase Map

_Update this file whenever a folder/project is added or a layer's
responsibility changes — see `.claude/skills/codebase-map/SKILL.md`._

---

## `backend/api/` — FastAPI service
Owns the HTTP surface only — never calls `ModelProvider` directly (see
`docs/context/04-agent-boundaries.md`).
- `app/main.py` — app + lifespan (RabbitMQ connection/topology), CORS.
- `app/config.py` — env vars (`RABBITMQ_URL`, `STORAGE_DIR`, queue names).
- `app/deps.py` — FastAPI dependencies: DB session, `Storage`, RabbitMQ channel.
- `app/queue.py` — topology declaration + `publish_job`.
- `app/ruleset.py` — reads `owner_ruleset.json` severities for display ordering.
- `app/schemas.py` — API request/response Pydantic models.
- `app/routers/units.py` — `GET /units`, `GET /units/{id}` (joined lease + fields + flags + rule evals + photo reports + work orders).
- `app/routers/leases.py` — `POST /leases` (upload → store → enqueue, 202).
- `app/routers/photos.py` — `POST /units/{id}/photos` (multi-file upload → enqueue, 202).
- `app/routers/jobs.py` — `GET /jobs/{id}` (poll target).
- `app/routers/review.py` — accept/reject/edit endpoints + `POST /leases/{id}/accept-unit-match` (the one occupancy-mutating action).
- **Pattern for a new endpoint**: route → Pydantic request/response → delegate to a service function or inline query — no business logic duplicated between routers.

## `backend/worker/` — RabbitMQ consumer
The only place `ModelProvider` is called from.
- `worker/main.py` — entrypoint (`python -m worker.main`); consumes both
  queues, manages `Job` status lifecycle, bounded retry → dead-letter.
- `worker/config.py`, `worker/queue.py` — same shape as the api side (see
  docstring there for why the topology is duplicated, not shared).
- `worker/deps.py` — `get_storage()`, `get_provider()` (the one place
  `StubModelProvider` is constructed — swap here for a real provider).
- `worker/document_text.py` — PDF/txt → plain text for `extract_lease`.
- `worker/handlers/lease_extraction.py` — extraction → rule engine → DB, idempotent (delete+reinsert by `lease_id`).
- `worker/handlers/photo_analysis.py` — photo assessment → DB, idempotent (delete+reinsert by `photo_report_id`).
- **Pattern for a new job type**: add a queue name + handler pair in both `queue.py`/`main.py`, document it in `docs/context/05-pipeline-architecture.md`.

## `backend/packages/agents/agents/` — the agent + rule-engine package
Shared by `api` (severities lookup only) and `worker` (everything else). No
DB dependency — see `docs/context/04-agent-boundaries.md`.
- `provider.py` — `ModelProvider` Protocol (`extract_lease`, `analyze_photos`).
- `schemas.py` — `ExtractedField`, `LeaseExtractionResult`, `PhotoAssessmentResult`, `WorkOrderDraft`.
- `stub.py` — the default `ModelProvider`: real regex/heuristic extraction over input text (not canned output) + filename-hint-based photo analysis. Read this file's docstring before touching it.
- `rules.py` — R1–R7 check functions, reading `docs/owner_ruleset.json` live via `paths.py`.
- `units_lookup.py` — static unit label→id matching from `docs/units.json` (identification only, never `status` — that's DB-only, see the module docstring).
- `paths.py` — `resolve_path(env_var, default)`: every `docs/*.json` default is env-var-overridable, because the container filesystem layout differs from local dev (this was a real bug caught during Docker verification — see ADR context in git history).
- **Pattern for a new agent capability**: extend the `ModelProvider` Protocol, implement in `stub.py`, document the contract in `docs/context/04-agent-boundaries.md` first.

## `backend/packages/db/db/` — persistence
Shared by `api` and `worker`.
- `enums.py` — every Python enum used in a DB column (kept separate from
  `models.py` so `base.py` can build a `type_annotation_map` without a
  circular import).
- `base.py` — `Base` + `type_annotation_map`, with `values_callable` forcing
  SQLAlchemy to write enum `.value` (e.g. `"available"`) instead of its
  default `.name` (`"AVAILABLE"`) — this mismatched the Postgres enum labels
  Alembic created and broke seeding until fixed; don't add a new enum column
  without adding it here too.
- `models.py` — `Unit`, `Lease`, `LeaseField` (EAV-style, ADR-006), `Flag`,
  `RuleEvaluation`, `PhotoReport`, `WorkOrder`, `Job`.
- `session.py` — async engine/session factory (`DATABASE_URL` env var, required).
- `seed.py` — loads `docs/units.json` into `units` (idempotent upsert); run via `python -m db.seed`.
- `migrations/` — Alembic; `versions/0001_initial_schema.py` is hand-written (matches `models.py` exactly), not autogenerated, since there was no live DB to diff against at the time it was written.
- **Pattern for a new field**: prefer a new `LeaseField` row kind over a new column (ADR-006) — a new column is only correct for a genuinely new entity attribute.

## `backend/packages/storage/storage/` — file storage
Shared by `api` (writes) and `worker` (reads). Added mid-build once it was
clear the worker needed the same interface, not just the API — see ADR-008.
- `storage.py` — `Storage` Protocol (ref-based: `save`/`read_bytes`/`read_text`, never raw paths at call sites) + `LocalDiskStorage`.
- **Pattern for a new backend**: implement the protocol, swap the constructor call in `worker/deps.py` / `app/deps.py` — no call-site changes.

## `frontend/` — Next.js (App Router)
- `app/page.tsx` — unit list.
- `app/units/[unitId]/page.tsx` — the "bringing them together" screen: lease panel (fields/rules/flags, each with `ReviewControl`) + issues panel (photo reports/work orders), plus the "accept unit match" action.
- `app/leases/upload/page.tsx`, `app/units/[unitId]/upload-photos/page.tsx` — upload flows, poll via `useJobPolling`.
- `components/ReviewControl.tsx` — the one shared accept/reject/edit component used for `LeaseField`, `Flag`, and `WorkOrder` alike (docs/context/06).
- `lib/api.ts`, `lib/types.ts` — API client + types mirroring `backend/api/app/schemas.py` (kept in sync by hand — see README "what I left out").
- `lib/useJobPolling.ts` — simple interval poll of `GET /jobs/{id}`.
- `tests/` — Vitest + Testing Library.
- **Pattern for a new review-able entity**: reuse `ReviewControl`, don't fork a new accept/reject implementation.

## `docs/context/` — the layered context system
See `CLAUDE.md` and `.claude/rules/context-layers.md`. Not application code;
read before writing application code.

## `docs/` (root files)
`solution-brief.md`, `owner_ruleset.json`, `units.json` — provided/derived
reference material. Read live by the backend at runtime — never copy their
content into code.

## `fixtures/`
Synthetic sample lease + photos (the property owner's real starter pack hadn't
arrived when this was built) — see `fixtures/README.md`. Used for manual
end-to-end verification and as the basis for `stub.py`'s tests.

## `specs/`
Per-feature `spec.md` + `plan.md`, created after plan-mode approval — see
`.claude/rules/plan-mode.md`.

## `.claude/`
Claude Code configuration — rules, skills, agents, permissions.

## `.github/workflows/`
- `ci.yml` — backend tests (pytest) + frontend lint/test/build, on push/PR.
- `ai-pr-review.yml` — posts an AI-generated review comment on PRs (needs an
  `OPENROUTER_API_KEY` repo secret; no-ops without one).

## Root files
- `docker-compose.yml` — postgres, rabbitmq, migrate (one-shot), api, worker, web.
- `.env.example` — for running services on the host against compose-managed postgres/rabbitmq.
